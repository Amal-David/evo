# Lessons

- Before adding another orchestration layer, inspect Evo's host conventions and the selected host's native agent tools. OpenCode already provides fresh-context `task` subagents; the missing integration was explicit headless propagation of Evo's `subagents`, `budget`, and `stall` controls, not a second dispatcher.
- A long-running benchmark campaign must refresh and rebase onto the promoted remote frontier deterministically. A prompt that merely tells the agent to re-check submissions is insufficient: stale Git ancestry plus a strict local-noise gate can spend days optimizing obsolete code while faster solvers advance the benchmark.
- On hardware-mismatched performance challenges, local measurements should rank official probes rather than prohibit them. A correctness-clean +0.01% point estimate is enough for an official probe; preserve only hard correctness, scope, freshness, attribution, deduplication, and secret gates, then use the daily quota on small positive, target-specific, neutral-but-plausible, and carefully bundled candidates.
- Treat OpenCode model selection as a live catalog decision. Rank only currently available free models, use the selected model's actual supported reasoning variant, and make wrappers reject model or variant drift instead of translating between incompatible settings.
